# Hunter

Сайт барбершопа Hunter с прайсом, мастерами, фотографиями, отзывами и контактами. Запись проходит в YCLIENTS. Собственной формы записи, таблицы заявок и отправки уведомлений о записи нет.

Интерфейс: HTML, CSS и JavaScript без библиотек интерфейса. Сервер: Node.js, Express, SQLite и Sequelize. Sharp обрабатывает фотографии.

## Как запустить

Нужна **Node.js 24 LTS**. Перед запуском и тестами проект проверяет версию и сообщает, как выбрать подходящую. В WSL с установленным nvm выполните `nvm use 24` в папке проекта; файл `.nvmrc` сам по себе версию не переключает. Версия 20 больше не поддерживается. Команды ниже выполняются из папки проекта.

1. Установите зависимости по зафиксированным версиям:

   ```bash
   npm ci
   ```

   При разработке можно использовать `npm install`. Сохраняйте `package-lock.json`.

2. Создайте `.env` из примера, только если своего файла ещё нет:

   ```bash
   cp .env.example .env
   ```

   В PowerShell: `Copy-Item .env.example .env`.

3. Заполните обязательные настройки:

   ```dotenv
   SITE_URL=http://localhost:3001
   ADMIN_LOGIN=ваш_логин
   JWT_SECRET=ваш_случайный_секрет
   ```

   Логин: 6–100 символов, секрет: минимум 32. Задайте свои значения. Случайный секрет можно получить командой:

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
   ```

4. Задайте пароль администратора:

   ```bash
   npm run admin:password
   ```

   Введите пароль длиной 12–100 символов дважды. Символы не показываются в терминале и не попадают в историю команд. Команда сама сохранит `ADMIN_PASSWORD_HASH` в `.env`; вручную копировать хеш не нужно. Для смены пароля используйте эту же команду и перезапустите сервер.

5. Запустите сайт:

   ```bash
   npm run dev
   ```

   Откройте `http://localhost:3001`. Панель управления: `/admin`.

Не заменяйте свой `.env` примером и не публикуйте секреты. После изменения `.env` перезапустите сервер.

При обновлении старой установки с полем `ADMIN_PASSWORD` выполните один раз `npm run admin:password -- --migrate`. Команда заменит открытый пароль его хешем и сохранит прежние данные для входа, остальные настройки останутся на месте. Старое поле удаляется. При обнаружении открытого пароля сервер объяснит, как выполнить этот перевод, и не запустится с устаревшей настройкой.

Хеш создаётся встроенным `scrypt` со случайной солью: N=32768, r=8, p=3. Параметры выбраны по [рекомендациям OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt) для ограниченной памяти. Проверка асинхронная, одновременно выполняются не более двух проверок входа. Пароль и его хеш команда не выводит.

## Настройки и управление

`PORT` по умолчанию равен `3001`, `HOST` равен `127.0.0.1`: сервер принимает локальные подключения. Для контейнера или локальной сети нужен подходящий `HOST` и отдельная настройка доступа. `SITE_URL` должен совпадать с адресом сайта, включая протокол и порт, без дополнительного пути.

На рабочем сервере задайте `NODE_ENV=production`, HTTPS-адрес `SITE_URL` и запускайте приложение за обратным прокси, например Nginx. Если прокси находится на той же машине, задайте `TRUST_PROXY=loopback`. Значение `true` также означает доверие только локальному прокси. Порт Node.js не требуется открывать в интернет. Для другого расположения прокси нужна отдельная настройка доверенных адресов.

В админке шесть вкладок:

- **Услуги:** название, категория, необязательное описание, цены барбера и топ-барбера, популярность и видимость. Хотя бы одна цена обязательна. Пустая цена означает, что эта категория услугу не оказывает. Общая цена существующих услуг сохраняется до установки отдельных цен.
- **Мастера:** имя, роль, необязательное описание, фотография и видимость.
- **Отзывы:** одобрение, отклонение и удаление. Посетители видят только одобренные отзывы; статистика считается по ним.
- **Фотографии:** загрузка, замена, необязательная подпись, раздел и удаление.
- **Контакты:** обязательный телефон и отдельные поля ссылок WhatsApp, Telegram, ВКонтакте, МАКС и Instagram. Пустая ссылка скрывает сервис. Добавление двух сервисов не меняет порядок работы формы.
- **Юр. документы:** политика и отдельные согласия на обработку и публикацию отзыва.

Телефон обновляется в шапке, контактах, ссылках звонка и микроразметке. Допустимы `+7 (999) 123-45-67`, `8 (999) 123-45-67`, 10 цифр российского номера либо полный международный номер с `+`. Ссылки проверяются по HTTPS и разрешённым доменам. Изменение телефона не меняет ссылку WhatsApp.

Для МАКС вставьте полную ссылку из приложения на домене `max.ru`, например на профиль `https://max.ru/u/…`. Для Instagram допустимы `instagram.com` и `www.instagram.com`. Другие домены, HTTP, адреса с логином, паролем или нестандартным портом отклоняются. Ссылки хранятся в существующей таблице `contact_settings`, иконки находятся в проекте и не требуют сторонних скриптов. Официальный знак МАКС взят из [брендбука](https://go.max.ru/brandbook) и оформлен в стиле остальных контактов.

Адрес, часы работы и реквизиты находятся в `client/pages/index.html`. Адрес и часы также указаны в микроразметке `server/services/pageService.js`: обновляйте оба места. До публикации заполните отмеченные поля юридических документов, проверьте реквизиты, цены и отзывы, замените демонстрационные фото подлинными.

## Запись и аналитика

Укажите в `.env` свою ссылку из YCLIENTS:

```dotenv
YCLIENTS_BOOKING_URL=https://n123456.yclients.ru/
```

Номер приведён для примера. Для адреса `https://n<номер>.yclients.ru/` без дополнительного пути и фрагмента после нажатия подключается официальный виджет. На компьютере он открывает боковую панель; на телефоне сервис может открыть форму в текущей вкладке. Расположение справа и отключение второй плавающей кнопки задаются в YCLIENTS.

Все кнопки записи используют `/booking`. Если виджет недоступен, остаётся обычный переход. Если ссылка не задана, сайт возвращает посетителя к блоку записи с предложением позвонить. Выбранные мастер и услуга пока не передаются в сервис. Цены с YCLIENTS не синхронизируются. Реальную запись нужно проверить после установки своей ссылки.

Необязательный `YANDEX_METRIKA_ID` включает уведомление об аналитике. До согласия счётчик сайта не загружается. Отказ тоже сохраняется; выбор можно изменить через «Настройки аналитики» в подвале. Если идентификатор не задан, уведомление и настройка скрыты. При отзыве разрешения страница перезагружается без счётчика, доступные сайту данные Метрики удаляются по возможности. Если на этой странице заполнен отзыв, перед подтверждением отказа появится предупреждение о потере ввода. Отмена предупреждения сохраняет текст и прежний выбор аналитики. Открытие настроек и работа с баннером сами по себе отзыв не сбрасывают. Первый отказ до запуска счётчика перезагрузки не требует. Без хранилища браузера выбор действует на текущей странице.

Разрешение относится к счётчику сайта. Яндекс Карты и YCLIENTS являются отдельными внешними сервисами. Шрифт Manrope хранится в проекте. Необязательные `UTM_SOURCE`, `UTM_MEDIUM`, `UTM_CAMPAIGN` добавляют метки к ссылкам контактов.

## Фотографии и интерфейс

Разрешены PNG, JPEG и WebP до 5 МБ и 40 мегапикселей. Проверяются MIME-тип, сигнатура и декодирование. Результат: WebP с качеством 82 и длинной стороной до 1920 пикселей, без увеличения и обрезки. Ориентация исправляется, метаданные удаляются, прозрачность сохраняется. Анимация не принимается. Одновременно обрабатываются максимум два изображения; при занятости повторите загрузку позже. Старые фото не перекодируются.

На компьютере мастера расположены сеткой по три карточки, неполный ряд выровнен по центру. До 1024 пикселей мастера, фото и отзывы листаются пальцем по одной карточке. Точек не более пяти. Автоматического перелистывания при чтении нет. Галереи на компьютере сначала показывают шесть фото, остальные открываются кнопкой. Увеличенный просмотр закрывается кнопкой, Escape или нажатием вне фото.

Несохранённые формы сбрасываются при закрытии, смене вкладки админки или выходе. JWT хранится только в памяти страницы и действует до часа. Выход отзывает его на сервере. Обновление страницы требует входа; перезапуск сервера закрывает все сеансы. Поддерживается до десяти одновременных сеансов. Приложение рассчитано на **один процесс Node.js**: сеансы и ограничения запросов хранятся в его памяти.

С одного IP можно отправить пять отзывов за десять минут, чтобы посетители общей сети не мешали друг другу. Ошибки заполнения лимит не расходуют. Каждый отзыв по-прежнему проходит проверку и появляется на сайте только после одобрения администратора.

## База, копии и обновления

По умолчанию база находится в `data/hunter.sqlite`. Относительный `DB_STORAGE` считается от корня проекта, абсолютный путь тоже допустим. Значение `:memory:` предназначено для тестов.

Первый запуск создаёт отсутствующий файл и восемь таблиц: `services`, `masters`, `reviews`, `photos`, `contact_settings`, `privacy_policy`, `consent_documents`, `review_consents`. Последняя хранит время и копии принятых документов с их версиями.

Повторный запуск подключает тот же файл и сохраняет записи. Автоматических миграций, `sync({ force: true })`, `sync({ alter: true })` и наполнения примерами нет. Удалённое содержимое не появляется снова. Новую базу заполняет администратор. До сохранения своих юридических текстов используются `server/*-default.txt`.

Если в старой таблице отсутствует обязательное поле, запуск остановится, сохранив данные. Текущая рабочая база сверена с моделями. Будущие изменения схемы потребуют отдельного преобразования, проверенного на копии. Удаление миграций не обновляет произвольную старую базу само по себе.

Перед обновлением остановите приложение и скопируйте **`.env`, весь каталог `data/` и `client/public/images/uploads/`** в закрытое место. Обычная файловая копия открытой SQLite-базы может быть несогласованной; без остановки используйте SQLite Backup API. Проверьте восстановление до удаления оригинала.

Обновляйте исходники и зависимости, сохраняя эти три части. Выполните `npm ci`, `npm test`, запустите приложение и проверьте `/healthz`, главную и админку. Не заменяйте рабочую базу тестовой и не кладите копии в `client/public/`. Установка запускает сборку нативных SQLite и Sharp: используйте доверенный реестр и lock-файл.

## Проверки и поддержка

```bash
npm start            # обычный запуск
npm test             # изолированные проверки без рабочей базы
npm run format       # единое оформление кода и документации
npm run format:check # проверка оформления без изменения файлов
npm audit            # известные уязвимости зависимостей
```

В stdout записываются время, событие, код ответа и номер запроса. Пароли, JWT, содержимое форм и SQL не записываются. Хранение журналов, ограничение срока хранения, наблюдение и оповещения настраиваются отдельно. `/healthz` проверяет ответ процесса, а не все внешние сервисы или свободное место.

См. [архитектуру](docs/ARCHITECTURE.md), [аудит](docs/SECURITY_AUDIT.md) и [чек-лист](docs/CHECKLIST.md). CSS содержит оглавление, разделы и адаптацию в конце. Комментарии и JSDoc написаны на русском.
