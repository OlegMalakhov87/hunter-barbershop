# Обновление приложения и сервера

Инструкция использует каталог `/var/www/hunter`, пользователя `deploy`, процесс PM2 `hunter` и домен `example.ru`. Подставьте параметры своего окружения. Системные команды Nginx и Ubuntu выполняются от `root`, команды приложения от `deploy`.

Первая установка описана в [DEPLOYMENT.md](DEPLOYMENT.md). Приложение использует один процесс Node.js 24.

## 1. Подготовка

Перейдите в проект и проверьте окружение:

```bash
cd /var/www/hunter
node -v
pm2 status
git status --short
git branch --show-current
```

Для `git pull` рабочее дерево должно быть чистым, а текущая ветка иметь связь с удалённой веткой. Просмотрите изменения моделей и новых параметров `.env.example` перед обновлением.

## 2. Резервная копия

Остановите приложение и другие подключения к SQLite. При стандартном `DB_STORAGE` выполните:

```bash
umask 077
backup_directory="$HOME/backups/hunter/$(date -u +%Y%m%d-%H%M%S)"
mkdir -p "$backup_directory"
pm2 stop hunter
git rev-parse HEAD > "$backup_directory/revision.txt"
tar -czf "$backup_directory/data.tar.gz" .env data client/public/images/uploads
tar -tzf "$backup_directory/data.tar.gz"
```

Копия содержит настройки, SQLite и фотографии. При нестандартном `DB_STORAGE` включите фактический файл базы и связанные файлы журнала. Копии находятся вне публичного каталога с ограниченным доступом.

Продолжайте обновление только после успешного создания копии.

## 3. Код и зависимости

Получите код из текущей удалённой ветки:

```bash
git pull --ff-only
npm ci --include=dev
```

`npm ci` устанавливает версии из `package-lock.json`. Параметр `--include=dev` включает Prettier для проверки форматирования. Каталоги `data/` и `client/public/images/uploads/`, а также `.env` сохраняются между выпусками. `node_modules` устанавливается на сервере и не переносится с другой системы.

Сверьте `.env` с `.env.example` и добавьте необходимые параметры, сохраняя действующие значения. Для рабочего окружения используются `NODE_ENV=production`, HTTPS-адрес `SITE_URL`, `HOST=127.0.0.1` и `TRUST_PROXY=loopback` при локальном Nginx.

## 4. Применение изменений схемы

Модели находятся в `server/models.js`. При отсутствии базы таблицы создаёт приложение. Для существующей таблицы команда добавления полей имеет вид:

```text
npm run db:migrate -- имя_таблицы новое_поле другое_поле
```

Замените имена параметров на реальные. Поля должны присутствовать в модели; типы и значения по умолчанию берутся из неё. Команда выполняется при остановленном приложении, только при добавлении полей.

`db:migrate` проверяет весь набор до записи, создаёт рядом с базой копию `hunter-before-migrate-*.sqlite` с правами `0600` и добавляет колонки одной транзакцией. Повторный запуск для существующих полей ничего не меняет.

Поддерживаются обычные поля с `NULL` или постоянным значением по умолчанию. Обязательные поля без подходящего значения, ключи, уникальность, связи и вычисляемые значения требуют отдельной миграции. Команда не переименовывает и не удаляет поля, не меняет типы и не переносит записи.

При наличии неперенесённых записей WAL команда прекращает работу. Не удаляйте `-wal` вручную: завершите подключения и используйте штатное резервное копирование SQLite.

Изменение схемы сначала проверяется на отдельной копии базы. При ошибке изменения схемы приложение остаётся остановленным до восстановления согласованных кода и данных.

## 5. Проверки и перезапуск

```bash
npm test
npm run format:check
pm2 restart hunter --update-env
pm2 save
pm2 status
curl -fsS http://127.0.0.1:3001/healthz
```

Перезапуск выполняется только при успешных проверках. Ожидаемый ответ `/healthz`: `{"status":"ok"}`. Приложение работает в режиме fork с одним экземпляром; кластерный режим не используется.

## 6. Настройка Nginx

Файл сайта: `/etc/nginx/sites-available/hunter`, ссылка подключения: `/etc/nginx/sites-enabled/hunter`. Полная конфигурация HTTPS и проксирования находится в [инструкции развёртывания](DEPLOYMENT.md#домен-nginx-и-https).

При изменении домена, порта или правил прокси создайте копию конфигурации и отредактируйте файл:

```bash
cp -L /etc/nginx/sites-available/hunter "/root/hunter-nginx-$(date -u +%Y%m%d-%H%M%S).conf"
nano /etc/nginx/sites-available/hunter
nginx -t
```

Конфигурация использует `proxy_pass http://127.0.0.1:3001`, передаёт `Host`, `X-Forwarded-Proto` и адрес посетителя. Nginx ограничивает тело запроса `client_max_body_size 5m`. HTTP и `www` перенаправляются на основной HTTPS-домен.

После успешного `nginx -t` примените конфигурацию:

```bash
systemctl reload nginx
```

Изменение Nginx не требует перезапуска Node.js. Изменение `SITE_URL` или других параметров приложения требует `pm2 restart hunter --update-env` под `deploy`.

## 7. Обновление системного ПО

Выполните под `root`:

```bash
apt update
apt list --upgradable
apt upgrade
```

Если системе требуется перезагрузка, выполняйте её после сохранения списка PM2 и проверки автозапуска.

При обновлении Node.js выполните шаг резервного копирования с остановкой приложения. Затем под `deploy`:

```bash
nvm install 24
nvm use 24
nvm alias default 24
npm install --global pm2
npm ci --include=dev
npm test
npm run format:check
pm2 restart hunter --interpreter "$(command -v node)" --update-env
pm2 save
pm2 show hunter
```

Приложение требует ветку 24.x. Перезапуск выполняется только после успешных проверок. Параметр `--interpreter` указывает PM2 на текущий исполняемый файл Node.js.

Обновите автозапуск по [инструкции PM2](https://pm2.keymetrics.io/docs/usage/startup/#updating-startup-script-after-nodejs-version-upgrade): выполните `pm2 unstartup` под `deploy`, затем напечатанную системную команду от `root`. После этого выполните `pm2 startup` под `deploy` и его команду установки службы от `root`. Под `deploy` сохраните список через `pm2 save`.

Для проверки продления сертификата используйте установленную команду Certbot:

```bash
certbot renew --dry-run
```

При установке через snap доступен путь `/snap/bin/certbot`. Таймер продления должен быть активен.

## 8. Проверка работы

```bash
curl -I http://example.ru/
curl -I https://www.example.ru/privacy
curl -I https://example.ru/
curl -fsS https://example.ru/healthz
```

HTTP и `www` должны возвращать перенаправление на основной HTTPS-домен с сохранением пути. Главная отвечает 200. Проверьте вход в админку, сохранение формы, загрузку изображения, отправку отзыва, карту, выбор cookies и запись через YCLIENTS.

Для диагностики процесса:

```bash
pm2 logs hunter --lines 100 --nostream
```

При неуспешном обновлении остановите процесс, сохраните текущее состояние отдельно и восстановите совместимые исходники и данные из копии. SQLite восстанавливается в чистый каталог при закрытых подключениях; распаковка поверх активного файла базы не используется. Затем проверьте права `deploy`, зависимости, запуск и HTTP-ответы.
