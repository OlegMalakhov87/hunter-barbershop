# Архитектура

## Стек

Приложение работает в одном процессе **Node.js 24**. **Express 4** принимает HTTP-запросы, отдаёт страницы, статические файлы и JSON API. **Sequelize 6** описывает модели и выполняет запросы к **SQLite** через пакет `sqlite3`. База находится на постоянном локальном диске.

Интерфейс использует HTML, CSS и JavaScript без сборки и библиотек интерфейса. Sharp проверяет и обрабатывает фотографии. Настройки окружения загружает `dotenv`. В рабочем окружении Nginx принимает HTTPS и передаёт запросы локальному процессу Express; PM2 управляет запуском процесса.

## Слои приложения

### Маршруты

Маршрутизация находится в `server/routes/`:

- `pages.js` сопоставляет публичные адреса и HTML-шаблоны, формирует `robots.txt` и `sitemap.xml`, обслуживает `/favicon.ico` и перенаправление `/booking`.
- `public.js` определяет открытое API каталога, фотографий, контактов, отзывов и версий документов.
- `admin.js` определяет вход, выход и операции панели управления.

Маршруты связывают URL с обработчиком, авторизацией и правилами проверки данных.

### Контроллеры

HTTP-обработчики находятся в `server/controllers/`. Контроллер читает параметры запроса, выбирает разрешённые поля, вызывает сервис или модель и формирует ответ с нужным кодом HTTP.

`catalogController.js` создаёт общий набор операций для услуг и мастеров с отдельными списками полей. `reviewsController.js` управляет отправкой и модерацией отзывов, `photosController.js` загрузкой и заменой фото, `settingsController.js` контактами и документами, `authController.js` входом и выходом.

### Сервисы

Прикладная логика находится в `server/services/`:

- `catalogService.js` подготавливает цены и выбирает разрешённые поля; `catalogViewService.js` строит HTML каталога.
- `pageService.js` подставляет данные и версии статических ресурсов в шаблоны.
- `privacyService.js`, `consentService.js` и `legalTextService.js` получают тексты документов, рассчитывают версии и формируют безопасную разметку.
- `photoStorage.js` проверяет и сохраняет изображения; `photoService.js` проверяет ссылки на файл перед удалением.
- `contactsService.js` получает контакты для панели и публичного интерфейса.
- `reviewRetentionService.js` удаляет просроченные отзывы; `logger.js` записывает технические события.
- `passwordService.js` создаёт и проверяет хеш пароля; `metricsService.js` формирует скрипт счётчика.

Простые операции чтения и записи выполняются в контроллере через модель. Общие правила и объёмные операции находятся в сервисах.

### Модели и подключение к базе

Схема и связи находятся в `server/models.js`. Функция `defineModels()` описывает модели для подключения Sequelize.

`server/database.js` создаёт подключение и экспортирует модели. `initDatabase()` проверяет поля существующих таблиц и создаёт отсутствующие таблицы. При недостающем поле запуск прекращается с ошибкой схемы. Автоматическое изменение типов и удаление таблиц отключены.

`server/config/storage.js` определяет одинаковый путь к базе для приложения и команды изменения схемы.

### Общие обработчики

`server/middleware/` содержит авторизацию, проверку ввода, ограничения запросов, обработку загрузок, защитные заголовки и учёт доступа к данным отзывов.

`server/utils/http.js` содержит `HttpError` для ожидаемых ошибок и `asyncRoute` для передачи отказа асинхронного обработчика в общий обработчик Express.

`server/app.js` подключает эти части, проверяет базу, запускает очистку отзывов и HTTP-сервер. При остановке он прекращает приём запросов, ожидает завершения очистки и закрывает подключение к базе.

## Прохождение запроса

Запрос изменения услуги `PUT /api/admin/services/:id` проходит следующие этапы:

1. Nginx передаёт запрос Express с адресом сайта, протоколом и адресом посетителя.
2. Общие обработчики назначают идентификатор запроса и защитные заголовки, проверяют Origin, ограничение частоты и размер JSON.
3. Административный маршрут проверяет Bearer-токен, идентификатор услуги и поля формы.
4. Контроллер выбирает разрешённые поля и подготавливает цены через сервис.
5. Модель Sequelize записывает данные в SQLite.
6. Контроллер возвращает JSON; общий обработчик ошибок формирует ответ при отказе.

Главная страница проходит через `renderPage()`. Услуги, цены, мастера и телефон подставляются сервером в HTML. `catalogViewService.js` экранирует значения карточек. Каталог доступен без выполнения JavaScript; фильтры управляют готовыми строками прайса в браузере.

`site.js` загружает фотографии, отзывы и статистику через API. `admin.js` обслуживает панель управления, `select.js` списки выбора, `privacy-consent.js` карту и аналитику. Общие стили находятся в `client/public/css/style.css`: переменные и общие элементы, разделы страниц, админка и адаптация.

## Безопасность

Аутентификация использует логин и scrypt-хеш из окружения. Команда `npm run admin:password` принимает скрытый ввод и атомарно записывает хеш в `.env`. Одновременно выполняются не более двух проверок пароля.

JWT передаётся в `Authorization: Bearer` и хранится в памяти страницы. Сервер проверяет алгоритм HS256, назначение, срок и идентификатор активного сеанса. Срок сеанса составляет один час, реестр содержит до десяти сеансов. Выход отзывает сеанс; перезапуск очищает реестр.

Cookie не используется для административной авторизации. Изменяющие запросы с чужим Origin отклоняются, CORS разрешает собственный origin из `SITE_URL`. `TRUST_PROXY=loopback` доверяет локальному прокси; значение по умолчанию отключает доверие пересылаемым заголовкам.

`express-validator` проверяет и нормализует входные данные. Контроллеры передают моделям только разрешённые поля. Динамический HTML использует `escape-html`, браузерные тексты вставляются через `textContent`. JSON-LD защищён от закрытия тега `script`. Helmet задаёт CSP со случайным nonce и остальные защитные заголовки.

Предел JSON составляет 16 КиБ, для юридических документов 96 КиБ, для контактов 64 КиБ. Загрузки ограничены 5 МиБ. Отдельные лимиты ограничивают общий поток API, неудачные входы, отзывы и загрузки. Сеансы, лимиты и счётчики обработки находятся в памяти одного процесса. Несколько экземпляров приложения требуют общего хранилища этого состояния.

Журнал приложения содержит разрешённые технические поля, идентификатор запроса и результат операции. Доступ к закрытым согласиям и действия с отзывами учитываются отдельно. Пароли, токены и содержимое форм в журнал не включаются. Ошибки API не раскрывают стек и SQL.

## Хранение данных

### SQLite

Путь к базе задаёт `DB_STORAGE`, по умолчанию `data/hunter.sqlite`. Относительный путь считается от корня проекта. `:memory:` создаёт базу в памяти для тестов.

База содержит восемь таблиц:

- `services`: услуги, категории, описание, общая цена, цены барбера и топ-барбера, популярность и видимость.
- `masters`: имя, роль, описание, фото и видимость мастера.
- `photos`: раздел галереи, подпись и путь к изображению.
- `reviews`: подпись, оценка, текст и статус модерации.
- `review_consents`: закрытые данные автора, время, условия публикации, версии и снимки трёх документов.
- `contact_settings`: телефон и ссылки на способы связи.
- `privacy_policy`: текст политики.
- `consent_documents`: тексты согласий на обработку и публикацию.

Модели содержат `createdAt` и `updatedAt`. Отзыв и его подтверждение связаны один к одному и создаются в транзакции. Удаление отзыва каскадно удаляет подтверждение.

Цены барбера и топ-барбера допускают `NULL`; пустая цена означает отсутствие услуги у этой категории. При наличии отдельных цен поле `price` равно минимальной из них. При отсутствии обеих категорий оно служит общей ценой. Подготовка цен едина для HTML, первого экрана и JSON-LD.

Общая команда `db:migrate` добавляет безопасные поля из моделей с резервной копией и транзакцией. Она не переименовывает и не удаляет поля, не меняет типы и не переносит данные. Порядок применения находится в [инструкции обновления](UPDATE_GUIDE.md#4-применение-изменений-схемы).

### Отзывы и документы

Публичный API отдаёт только одобренные отзывы и разрешённую подпись. ФИО, телефон, условия и снимки согласий доступны через защищённый маршрут админки. Проверка формата телефона и ФИО не подтверждает личность автора.

Тексты политики и согласий находятся в базе. При отсутствии записи используются `server/*-default.txt`. Сервер проверяет версии действующих документов перед отправкой отзыва и сохраняет точные тексты с подтверждением. Редактирование документа не меняет снимки согласий.

Очистка использует `server/config/reviewRetention.js`. Неопубликованные отзывы хранятся 30 дней с отправки, опубликованные и подтверждения не дольше 730 дней. Подтверждение удаляется вместе с отзывом. Очистка работает при запуске и каждые 24 часа порциями по 100 записей.

SQLite и резервные копии содержат закрытые данные без шифрования полей приложения. Доступ к ним ограничивается средствами операционной системы. Очистка таблиц не удаляет данные из резервных копий и свободных страниц файла.

### Фотографии

Файлы находятся в `client/public/images/uploads/`. База содержит локальные пути к ним.

Sharp проверяет MIME, сигнатуру, декодирование и предел 40 мегапикселей, исправляет поворот, обрезает кадр и создаёт WebP без метаданных. Предел длинной стороны составляет 1920 пикселей, качество 82. Одновременно обрабатываются до двух файлов. Исходник отдельно не хранится.

Требования в `server/config/images.js` используются сервером и админкой: мастера 4:5, минимум 720 × 900; галереи 4:3, минимум 900 × 675. Минимум проверяется после обрезки.

Имя файла содержит случайный UUID. Новый файл удаляется при отказе записи в базу. Прежний файл удаляется только при отсутствии ссылок из таблиц мастеров и фотографий. HTML, SVG и скрипты из uploads не выдаются.

### Внешние сервисы

Карта и Метрика подключаются после согласия. Выбор хранится в localStorage 180 дней. Отказ отключает их загрузку, настройки доступны в подвале.

YCLIENTS подключается по нажатию записи. `/booking` перенаправляет на адрес из окружения или к контактам при пустой настройке. Поля отзыва не передаются кодом сайта в счётчик, мессенджеры или форму записи.
