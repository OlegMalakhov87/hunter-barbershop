# Устройство проекта

Один процесс Express отдаёт страницы, файлы и JSON API. SQLite хранится на диске. Отдельная сборка интерфейса, очередь заданий и дополнительные серверы этому сайту не нужны.

```text
client/pages/           главная, админка, политика, два согласия
client/public/css/      style.css с оглавлением и адаптацией
client/public/js/       site.js, admin.js, select.js, metrics-consent.js
client/public/fonts/    локальный Manrope и лицензия
client/public/images/   изображения, uploads/ для загрузок
server/app.js           сборка приложения и запуск
server/config/          .env, телефон, ссылки, запись
server/scripts/         скрытая настройка и разовый перевод пароля администратора
server/routes/          адреса страниц и API
server/controllers/     обработчики запросов
server/services/        общая логика документов, изображений, страниц, журнала
server/middleware/      авторизация, валидация, заголовки и ошибки
server/utils/http.js    общие HTTP-ошибки и обработка async-функций
server/models.js        текущие восемь моделей Sequelize
server/database.js      подключение и инициализация базы
server/*-default.txt    начальные тексты документов
test/                   изолированные проверки Node.js
data/                   рабочая база, вне публичной папки
```

## Как проходит запрос

Сохранение услуги проходит через общие заголовки и ограничение запросов, Bearer-токен, правила `express-validator`, контроллер и модель Sequelize. Контроллер выбирает только разрешённые поля. Ожидаемая ошибка становится ответом 4xx, неожиданная обрабатывается в одном месте без раскрытия стека и SQL.

Маршрут определяет адрес. Контроллер отвечает за HTTP-запрос. Сервис выделен там, где логика общая или объёмная: обработка фото, версии согласий, подстановка в HTML. Обычные вызовы модели не обёрнуты в дополнительный слой ради самого слоя.

Для услуг и мастеров используется общий небольшой контроллер с явными списками полей. Три юридические формы настраиваются одной функцией. Проверка контактов общая для сохранения и чтения. Удаление файла проверяет, не используется ли он другой записью.

## Границы данных

Публичное API отдаёт активные услуги и мастеров, одобренные отзывы, статистику, фото, контакты и опубликованные документы. Отправленный отзыв получает статус `pending`. Снимки согласий не входят в публичные ответы. Имена, тексты форм и версии согласий не попадают в журнал.

JWT находится в памяти браузера, сервер хранит идентификатор активного сеанса. Выход и перезапуск закрывают его. Схема рассчитана на одного администратора и один процесс. Для нескольких процессов потребуются общие хранилища сеансов и ограничений запросов.

В `.env` находится только `ADMIN_PASSWORD_HASH`. Проверка `scrypt` асинхронная, выполняется не более двух проверок одновременно. Команда `npm run admin:password` принимает пароль без отображения в терминале и атомарно обновляет настройку. Пароль и хеш не выводятся в журнал. `server/config/runtime.js` проверяет Node.js 24 перед запуском и тестами; проверка окружения также защищает прямой запуск приложения.

## Как менять код

Для нового поля сначала определите модель и валидацию, затем явный список полей контроллера и форму. Изменение модели не меняет существующую таблицу автоматически: работайте с копией базы и планируйте перенос данных отдельно.

В CSS идут переменные и общие элементы, формы, разделы главной, документы, админка и адаптация. Добавляйте правила в соответствующий раздел, не создавайте случайные переопределения в конце.

Тесты используют отдельные базы и очищают свои файлы. Они не подключаются к рабочему `data/hunter.sqlite`. Перед передачей запускайте `npm test` и `npm run format:check`.
